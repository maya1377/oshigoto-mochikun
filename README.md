# おしごとモチくん

**[ブラウザーで遊ぶ](https://maya1377.github.io/oshigoto-mochikun/)**

次々届く仕事を処理し、疲労を管理して定時退勤する短時間の静的ブラウザゲーム。日本語UI、マウス操作。小さい画面にも対応。１プレイの目安は２〜３分。

## 遊び方

「出勤する」で開始。仕事カードを選んで行動する。考えている間は時間が進まない。

- **仕事**：30分、最大3進捗、疲労+18（疲労70以上は+22）。
- **休憩**：30分、疲労-32。
- **先送り**：各仕事１回、15分、疲労-8。引き継ぎメモで仕事量+1、受信箱の最後へ移動。今日中の完了は必要。
- 17:00までに６件すべて完了、疲労100未満で勝利。疲労100または定時に未完了で敗北。
- 後から届く仕事も６件に含む。到着時刻を受信箱に表示。すべて終えたら「定時までひと休みして退勤」。
- 結果画面から再プレイ。仕事名は３パターンで日替わり、数量と時刻は同じ。

## 起動・ビルド・検証

Node.js 22.18以上（ローカル検証24.21、GitHub Actionsは24）。

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

実Chromeの操作試験：

```sh
npm run build
npm run test:browser
npm run test:published
```

ブラウザー試験にはローカルにGoogle Chromeが必要。`test:browser` は検証専用プロフィールとHTTPサーバーで配信用distを試験し、終了時に片づける。`test:published` は上記の公開URLで、ローカルdistと同じアセットが配信されていることと主要操作を確認する。別の版を公開したあとに実行する場合は、先にローカルも同じ版でビルドする。

## 技術・制作判断

Phaser 3.90 / TypeScript 5.9 / Vite 7.3.7。Game Studioの2D標準ルートを採用。Phaserはオフィスと表情・時計を描画、DOMは日本語の説明と操作を担当。ゲームのルールは純粋な状態更新として独立し、描画やアニメーションに勝敗を依存させない。

行動選択式にして、思考中に時計が進まないようにした。後から届く仕事の時刻を先に示し、初見で予想できる忙しさにした。音声より低負荷の2D表現と操作の分かりやすさを優先。動きを減らす設定にも対応。

実行時の外部API、認証、DB、外部フォント、CDNは不要。ゲーム状態を外部送信しない。配信用distをHTTPで配信する（file://直接起動は対象外）。

## Game Studio利用記録

|スキル|担当工程・実際に適用した内容|
|---|---|
|Game Studio|2D標準ルートと制作工程の選択|
|Web Game Foundations|ルールと描画の分離、行動マッピング、保存境界|
|Phaser 2D Game|薄い描画シーン、DOM操作画面、状態から導く表情|
|Game UI Frontend|紙とオフィスの配色、状態の優先順位、画面幅対応、動きを減らす設定|
|Game Playtest|主要行動・勝敗・再プレイの実Chrome試験、検証画像の目視と修正|

スキルは工程の指針として使用。専用の自動生成・自動公開APIではない。Sprite Pipelineと3D関連は目的に不要なため未使用。画像生成や既存LINEスタンプ、個人素材は使わず、本案件専用のオリジナル仮キャラクターをSVGとPhaserの図形で作成。１人の担当AIで設計から納品まで実施。

制作上の問題は、一括保存のWindows文字数制限、描画メソッドの型エラー、初期開発ツールの既知問題、Gitの未認証、細い画面での数値改行。ファイル単位の保存、描画修正、修正版依存への更新、接続済みGitHubツールによる納品、数値表示の整形で対応した。詳細は [制作・検証記録](verification/REPORT.md)。

## ファイル・素材と保存先

ローカル保存先は、まやが指定した専用フォルダー `MyGames/oshigoto-mochikun`。他のゲームの素材やフォルダーを利用していない。

- `src/model.ts`：時間・仕事・疲労・勝敗。
- `src/main.ts`、`src/markup.ts`：日本語UI、操作、開始・結果画面。
- `src/office.ts`：オフィスとモチくん、表情、時計。
- `src/style.css`：テーマ、レスポンシブUI。
- `public/mochi.svg`：専用キャラクターとアイコン。
- `public/THIRD_PARTY_NOTICES.txt`：PhaserとEventEmitter3のライセンス。
- `tests/`：ルール・実Chrome・公開版の試験。
- `verification/REPORT.md`：工程・判断・検証結果・制約。
- `verification/screenshots/`、試験結果JSON：ローカルの検証資料（Git対象外）。
- `dist/`：ローカル配信用成果物（生成物はGit対象外）。
- `.github/workflows/`：継続テスト・ビルド・公開。

## 静的配信・GitHub Pages

`npm run build` の `dist/` を静的ホスティングへ配置する。baseは相対指定なのでリポジトリ配下で動く。

このリポジトリのPagesは、まやの明示承認を受けて **Settings → Pages → Source: GitHub Actions** に設定済み。mainへ変更が反映されると、テスト・ビルド・Pages公開が実行される。カスタムドメインや追加の秘密情報は不要。別環境へ移す場合は、そのリポジトリでもPagesの配信方式を設定する。
